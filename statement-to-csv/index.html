How it works

Most converters ask you to email or upload a document that lists every purchase you made last month. This one reads the file in the browser tab you already have open.

1

Read the page geometry

The PDF's text is extracted with its coordinates, then rows are rebuilt by grouping items that sit on the same baseline.

2

Find the money columns

Amounts are clustered by their right edge, which is how statements align them. That is what separates debit, credit and balance without knowing the bank.

3

You confirm, then export

Roles are guessed and shown for correction. Drop any row that shouldn't be there and take the CSV.

Questions

Are my statements really not uploaded?

Correct. The page loads a PDF reader and does the parsing in JavaScript on your machine. There is no backend, no database and no account system — the site is a set of static files. You can confirm it by opening your browser's network tab while you convert, or by disconnecting from the internet after the page loads.

Which banks does it support?

It isn't built per-bank. It reads the layout geometry, so it handles most statement formats from retail banks, credit cards and brokerages. When the automatic guess is wrong, you correct the column roles yourself, which is why unusual formats still work.

My statement is a scan and nothing was found.

Scanned or photographed statements are images with no text layer, so there is nothing to extract. Run the file through OCR first — macOS Preview, Adobe Acrobat and most scanner apps can add a text layer — then convert it here.

What do I actually get for $29?

A licence key that removes the row limit and enables batch conversion, on every browser and machine you use, permanently. There is no renewal.

Can I get a refund?

Yes — within 30 days, no questions. Convert a real statement on the free tier before paying and you will already know whether it reads your format correctly.
